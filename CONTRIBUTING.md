## How to contribute

1. For larger changes, open an issue first, so we can agree on the approach.
2. Fork the repository and create a branch from `develop`.
3. Keep the checks below green; they also run in CI.
4. Open a pull request against `develop` and describe what changes for users.

## Development setup

You need Python 3.12, Node.js 22 and a checkout of
[Halumar/contracts](https://github.com/Halumar/contracts) at the tag named in
[`.github/contracts-ref`](.github/contracts-ref).

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r halumar/rootfs/opt/hub/requirements.txt \
            -r halumar/requirements-dev.txt -r .github/requirements-ci.txt
export CONTRACTS_DIR=/path/to/contracts   # without it the contract tests are skipped locally

cd frontend && npm ci
```

The server expects the app's `/data` volume (database, key file, certificate, images), so it runs
inside the app container. For work on the admin page, `npm run dev` in `frontend/` starts a dev
server that proxies `/api` to `http://localhost:8099`; the Playwright tests mock the API completely
and need no running hub.

## Checks

CI runs these on every pull request (`.github/workflows/ci.yml` and `frontend.yml`):

| Area | Command |
|---|---|
| Lint and format | `ruff check halumar/rootfs/opt/hub/` and `ruff format --check .` |
| Tests with coverage gate | `cd halumar/tests && python -m pytest --cov=../rootfs/opt/hub --cov-fail-under=75` |
| Database transactions only in `database.py` | `python halumar/scripts/check_db_commits.py --strict` |
| Known vulnerabilities in Python packages | `pip-audit -r halumar/rootfs/opt/hub/requirements.txt` |
| Vendored API docs assets | `scripts/update-api-docs.sh --check` |
| Same version everywhere | `scripts/ci/check-versions.sh` |
| Contract (OpenAPI snapshot, data files, test vectors) | `scripts/ci/contracts-check.sh` (uses `CONTRACTS_DIR`) |
| Brand names | `scripts/brand-check.sh` (uses `CONTRACTS_DIR`) |
| Public texts (no ticket numbers, internal paths or test-network addresses) | `python "$CONTRACTS_DIR/tools/publiclint/publiclint.py" .` (exceptions with a reason in `.public-lint.toml`) |
| Icon tables, bundle licenses, third-party notices | `cd frontend && npm run icons -- --check && npm run licenses`, then `python scripts/third_party_notices.py --check` |
| Admin page | `cd frontend && npm audit --omit=dev && npm run check -- --fail-on-warnings && npm run build && npx playwright install chromium && npm run test:e2e` |

The built admin page under `halumar/rootfs/opt/hub/static/` is committed, because the image copies
it as is. Rebuild it with `npm run build` when you change the frontend; the release workflow builds
it again from source.

## Commit messages

- Subject in English, in the imperative ("Add …", "Fix …"), at most 72 characters.
- No internal ticket or finding numbers, no internal host names or addresses.
- Describe security fixes by their effect for users, not by how to exploit the problem.

## Dependencies and assets

- A new dependency must use a license that is compatible with the AGPL-3.0
  (`ALLOWED` in `scripts/third_party_notices.py`). Run `npm run licenses` in `frontend/`
  and `python scripts/third_party_notices.py` and commit the updated
  `THIRD_PARTY_NOTICES.md`.
- `halumar/rootfs/opt/hub/requirements.txt` pins every Python package of the image with `==`,
  the transitive ones after the `# Transitive` line. After changing a pin, install the file
  and run `python scripts/third_party_notices.py`; `--check` names missing, unused and
  outdated pins.
- Do not add logos or trademarks of other companies (including the Home Assistant logo).
  The MDI icon tables are generated by `frontend/scripts/gen-mdi-icons.mjs`
  (`npm run icons`), which leaves out brand icons.
- Only contribute code you wrote yourself or that is available under a compatible
  license; name its origin in the pull request.
